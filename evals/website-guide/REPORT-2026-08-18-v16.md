### Included because it adds value without adding facts

- The identity module now says the guide is automated and is not Fortune staff.
- The selected style module requires plain, respectful, nonjudgmental language,
  begins with the useful answer/action, and avoids jargon, blame, and assumptions.
- Server privacy detection now covers the bounded phrase categories already held
  by the browser. This remains a code control, not a model promise.
- Human handoff remains a server-owned route rather than generated advice.

### Excluded from the system prompt

- A blanket claim that active conversations are logged. Capture differs by
  environment and production remains `none`.
- Unapproved crisis destinations, onsite directions, multilingual-staff
  promises, or cross-site general knowledge.
- A global tutoring mode, which would require approved practice content and a
  separate evaluation contract.
- Program names, eligibility rules, schedules, availability, and contact facts.
  Those stay in current source records so source changes alter answers.

The compiled prompt therefore gains tone and identity guidance, not a second
knowledge base. See [`prompts/current.md`](../../prompts/current.md) and the
version/hash registry in [`prompts/manifest.json`](../../prompts/manifest.json).

## Prompt architecture

V16 composes a small fixed contract from server-owned identity, grounding,
privacy/instruction, abstention, and JSON-schema modules plus bounded reviewed
variants for style, clarification, follow-up behavior, and page awareness.
Prompt Lab can propose edits to the four presentation areas, but proposals do
not activate themselves. A developer must translate an accepted suggestion
into a named, code-reviewed variant and run the same release gates.

Historical artifacts preserve reconstructed v1, v1-short, v2, v3, v5, v8,
v9, and v10 contracts and authored v11–v16 releases. Every captured v16 turn
records `prompt_policy_version=2026-08-17-v16`.

## No-canned-response mechanism

1. The server resolves the active page and/or full-site candidates.
2. It sends only bounded approved excerpts, the resolved question, and the
   latest relevant guide answer to the model.
3. The model must return one candidate ID plus an answer, or a necessary `ASK`.
4. The server validates source ID, query support, numbers and units, entities,
   current-status polarity, universal claims, lexical grounding, and repetition.
5. A recoverable draft gets one reviewed retry. A second invalid draft becomes
   clarification or handoff; no factual template is substituted.
6. Without a model, factual questions abstain instead of using extracted or
   hard-coded copy.

Regression tests mutate source evidence and prove that old facts are rejected
and newly supported facts are accepted. They also prove that multiple different
grounded model phrasings can pass; wording variation is not encoded as a list of
answers.
