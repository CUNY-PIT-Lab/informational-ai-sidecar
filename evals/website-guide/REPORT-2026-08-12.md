# Website Guide evaluation — 2026-08-12

## Scope

This release evaluates the guide as a bounded public-source router, not as a general chatbot. The fixed suite contains 41 scattershot cases across nine slices and explicitly covers every server-owned request kind and every participant-facing response kind.

| Request kind | Representative case | Expected response |
| --- | --- | --- |
| clarification | “How can I get started?” | clarify |
| navigation | “What does this page say?” | answer |
| privacy | an email address in the question | privacy |
| procedure | “How do I sign up for a class?” | answer |
| retrieval | “Can I get a free laptop?” | answer |
| sensitive | a health-benefits question | handoff |

The response-kind inventory is `answer`, `clarify`, `handoff`, and `privacy`.

## Baseline diagnosis

The pre-fix production run completed all 41 cases but blocked release:

- 26/41 cases passed overall.
- 24/34 required cases passed.
- Four hard-gate cases failed.
- Median latency was 237.28 ms; p95 was 2,100.59 ms.
- 15/41 requests called the model.

The latency split was structural. Deterministic clarifications and safety responses usually completed in 150–250 ms over the public network, while model-routed answers took roughly 1.5–3.4 seconds. The model’s prose was then discarded in favor of source-extractive copy, so many confident requests paid model latency without improving the displayed answer.

## Changes

- Added typo normalization for common participant phrasing.
- Removed HTML wrappers and prompt-override clauses before routing or model use.
- Prioritized reviewed device, training, calendar, registration, individual-support, and contact routes.
- Kept the current page only when the participant refers to it or it is the top evidence match.
- Added short page summaries for page-aware questions.
- Added a server-side 600-character limit.
- Moved high-confidence source matches to a deterministic answer path.
- Reduced the model pack from seven records to three and shortened each excerpt for uncertain fallback requests.
- Removed model warmup from the Pages and Wix send paths.
- Reduced the visible answer ceiling from 48 to 32 words and limited factual extraction to one sentence.
- Updated the evaluator to report latency, copy length, and model calls by request and response kind.

## Published browser runs

GitHub Pages workflows `31566236071` and `31566534851` completed successfully. Live asset hashes matched the tested files.

The first published browser pass caught a simulation-layer defect outside the API benchmark: `?page=/trainings` rendered the home mock because that reviewed route was absent from the latest Wix snapshot. The API therefore received home-page context. Pull request 11 restored a minimal reviewed Training, Individual Support, and Contact context map before page selection, without adding those routes to the captured Wix inventory.

After that fix, six fresh published runs passed:

| Request kind | Typed question | Browser result |
| --- | --- | --- |
| clarification | “How can I get started?” | one short question and three buttons |
| retrieval | “Can I get a free laptop?” | 13-word source-backed answer |
| navigation | “What does this page say?” on Training | correct Training context and summary |
| procedure | “How do I sign up for a class?” | 14-word registration answer |
| privacy | an email address in the question | local hold marked `Not sent`; address not echoed |
| sensitive | an emergency internet request | short staff handoff |

Each request was activated with Return. All six browser consoles had zero warnings or errors. Screenshots are intentionally kept outside the repository at `/tmp/fortune-guide-{clarification,retrieval,navigation,procedure,privacy,sensitive}.png`.

The production Railway HTTP-log query found no 5xx response in the post-release window. Runtime request records contain only request ID, method, path, status, and duration metadata; they do not contain participant message bodies.
