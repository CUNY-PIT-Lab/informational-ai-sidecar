# Website Guide evaluation — 2026-08-12

## Scope

This release evaluates the guide as a bounded public-source router, not as a general chatbot. The fixed suite contains 41 scattershot cases across nine slices and explicitly covers every server-owned request kind and every participant-facing response kind.

| Request kind | Representative case | Expected response |
| --- | --- | --- |
| clarification | “How can I get started?” | clarify |
| navigation | “What does this page say?” | answer |
| privacy | an email address in the question | privacy |
| procedure | “How do I sign up for a class?” | answer |
| retrieval | “Can I get a free laptop?” | answer |
| sensitive | a health-benefits question | handoff |

The response-kind inventory is `answer`, `clarify`, `handoff`, and `privacy`.

## Baseline diagnosis

The pre-fix production run completed all 41 cases but blocked release:

- 26/41 cases passed overall.
- 24/34 required cases passed.
- Four hard-gate cases failed.
- Median latency was 237.28 ms; p95 was 2,100.59 ms.
- 15/41 requests called the model.

The latency split was structural. Deterministic clarifications and safety responses usually completed in 150–250 ms over the public network, while model-routed answers took roughly 1.5–3.4 seconds. The model’s prose was then discarded in favor of source-extractive copy, so many confident requests paid model latency without improving the displayed answer.

## Changes

- Added typo normalization for common participant phrasing.
- Removed HTML wrappers and prompt-override clauses before routing or model use.
- Prioritized reviewed device, training, calendar, registration, individual-support, and contact routes.
- Kept the current page only when the participant refers to it or it is the top evidence match.
- Added short page summaries for page-aware questions.
- Added a server-side 600-character limit.
- Moved high-confidence source matches to a deterministic answer path.
- Reduced the model pack from seven records to three and shortened each excerpt for uncertain fallback requests.
- Removed model warmup from the Pages and Wix send paths.
- Reduced the visible answer ceiling from 48 to 32 words and limited factual extraction to one sentence.
- Updated the evaluator to report latency, copy length, and model calls by request and response kind.

## Multi-turn information retrieval

A second fixed suite evaluates stateful retrieval rather than isolated prompts. It contains 13 conversations and 55 turns across device programs, class content and progression, individual support, certifications, practice and assessments, Spanish-language retrieval, program information, registration, context isolation, and ambiguous model source selection. Thirty-two turns depend on conversation context. The browser protocol sends at most six history messages, matching the published guide's three-exchange context window.

The pre-fix production run blocked release:

- 0/13 complete conversations passed; one failed turn fails its entire conversation.
- 28/55 individual turns passed.
- 14/32 context-dependent turns passed.
- Median latency was 323.60 ms; p95 was 1,273.44 ms.
- Four turns called the model, and no infrastructure failure occurred.

The failures were retrieval failures rather than transport failures. Short follow-ups such as “What does it cover?”, “What are they for?”, and “What should I take after that?” lost the active topic. Broad training pages also outranked reviewed class pages, specific openings were over-clarified, and topic changes could inherit the wrong route.

The fix carries only the latest explicit safe participant topic into genuinely elliptical follow-ups. It does not copy assistant prose into the routing query, and explicit topic shifts replace rather than accumulate context. Reviewed source preferences now cover the tested class, device, certification, assessment, individual-support, registration, partner, impact, and Spanish-language paths. Ambiguous source packs still go to the bounded model selector.

The real staging model passed 13/13 conversations, 55/55 turns, and 32/32 context-dependent turns on deployment `3b556eaa-fe53-43bb-a636-887b43c7f825`. The two deliberately ambiguous retrieval turns called the model and passed. Median latency was 346.42 ms; p95 was 421.28 ms. Staging retained its approved synthetic transcript boundary. The post-run aggregate audit selected no message content and found no privacy, role-order, orphan, duplicate, or unsafe-review defect, but it remains blocked by two stale pending turns that require separate cleanup.

Production deployment `66214c6c-60e3-47ea-a825-d7a8f1c3c26f` then reached terminal `SUCCESS`. Its fixed suite result was:

## Bounded selector v5

The prior v4 contract asked the model to generate a response kind, participant-facing message, rationale, and source IDs from three candidates. That made the prompt harder than the actual task and still required the server to discard or police model prose. Version 5 narrows the provider-independent contract to one decision: select one ID from up to ten approved candidates or return `ASK`. The provider receives the server-resolved question and approved candidate excerpts, never raw conversation history. Participant-facing text is extracted and validated by the server from the selected source; malformed output, an unapproved ID, unsupported distinctive terms, or weak evidence becomes a compact clarification rather than a guess.

The retrieval inventory contains 145 answer-authority records. All 144 substantive records are reachable by public title; the remaining `/about/partners` record is excluded because the captured Wix page is template filler. Partner questions use the actual About-page logo records. The same source audit corrected a factual error: Fortune's page says free refurbished laptops through Computers 4 People have limited supply and may take time, while mobile-device distribution—not laptop distribution—is on hold.

The expanded v5 staging suite added Tech Fair Q&A and About/team deep-page retrieval and now contains 14 conversations and 59 turns. After preserving each failed canary artifact and fixing the shared routing rules, deployment `0623da79-0032-4f7d-8a90-d54e7a668c91` passed 14/14 conversations, 59/59 turns, and 35/35 contextual turns. Median latency was 282.98 ms and p95 was 375.71 ms; one ambiguous Excel turn called the real model and returned a clarification. The other 58 turns used deterministic source-backed routing.

The fixed suite exposed one stale grader expectation after the Spanish beginner request improved from a broad Training route to the exact `Alfabetización Digital Básica en Español` page. The failed artifact is retained, the accepted source term was added explicitly, and the suite version advanced from 1.0.0 to 1.0.1 before its final rerun. Staging kept its approved synthetic transcript boundary throughout; none of these runs authorizes production participant capture.

The published UI also completed a seven-turn topic-switch conversation using Return for every send: device access, device programs, Excel formulas, an elliptical class follow-up, an explicit switch to Canva, another elliptical follow-up, and registration. It rendered seven user and seven guide messages in one conversation, with 133–354 ms observed browser response times and no console warning or error. The screenshot is kept outside the repository at `/tmp/fortune-guide-multiturn-production.png`.
